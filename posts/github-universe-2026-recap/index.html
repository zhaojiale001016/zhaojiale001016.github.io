GitHub Universe 2026 散场后，我记下了这几个数字

技术资讯 2026-11-05 约 5 分钟读完 · 阅读 - 次

GitHub Universe 2026 上周在旧金山开完，没能去现场，但这几天陆续读了几篇参会者的复盘（DEV 上这篇写得最细），再结合官方 Octoverse 报告的数字，有几件事值得拿出来说说。

先看体量

平台现在有超过 2.25 亿开发者，过去一年里平均每秒钟就有一个新用户注册，这已经是连续第二年保持这个速度。

2026 年的 Octoverse 报告里另外几组数更夸张：全年代码推送 179 亿次，比 2024 和 2025 加起来还多；公私仓库合计提交 343 亿次，是两年前的三倍多；合并的 PR 有 13 亿个，摊下来每天约 350 万个。

这些曲线变陡的时间点，和 AI 编程工具普及的时间点基本是重合的。提交量的通胀，我在上一篇里聊过它的代价，这里不重复。

图源：DEV Community《GitHub Universe 2026: My Recap from San Francisco》

Copilot 不想只当助手了

这届 Universe 的产品发布，主线是把 Copilot 从”帮你补全代码”往”协调整个交付流程”推。

新的 Copilot 应用里，Projects 负责跨仓库协调工作，Fusion 管模型选择，Automations 可以响应生产环境的信号自动触发任务，代码审查环节也被接进了这条链。配合能力在不同工具之间延续的 Session continuity，GitHub 想覆盖的明显是”从需求到上线”的全程，而不只是写代码那一段。

另一件容易被忽略但可能更重要的事：GitHub 在重建底层的 Git 基础设施。一个月几十亿次提交的冲击下，老地基扛不住了。这件事没什么传播度，但决定了上面那些花活能不能跑得稳。

图源：DEV Community《GitHub Universe 2026: My Recap from San Francisco》

闭幕主题演讲了一个相反的故事

有意思的是第二天。闭幕 keynote 没讲产品，讲的是开源维护者怎么活下去。

当 AI 让提 PR 的成本趋近于零，维护者面对的是雪片一样飞来的、质量参差的自动生成 PR。一个热门仓库的维护者每天要花大量时间分辨哪些 PR 背后真有人的思考。大会专门讨论了怎么保护维护者不被这波洪流淹掉，还谈了一个我很认同的判断：DevOps 的成熟度才是上 Coding Agent 的前提条件。流水线一团糟的团队，Agent 只会把混乱放大。

还有个提法叫 collaborative planning，大概是想让 AI 编程从”一个人对着提示词单打独斗”变成”多人一起规划、Agent 执行”的模式。方向对不对不好说，但起码承认了现在这种玩法有天花板。

我的两点 takeaway

一是平台在赌”工作流”而不是”生成”。代码生成能力各家迟早拉平，谁把生成前后的环节（规划、审查、部署、回滚）接住，谁才有护城河。这对我们做工具选型的启示是：别只比模型，要看工具在你整条流水线上的位置。

二是”人的判断”正在被明确定价。闭幕主题把维护者、审查者、DevOps 工程师推到台前，等于官方承认了一件事：AI 能写代码之后，稀缺的是知道该写什么、敢为结果签字的人。这个趋势和最近招聘市场的变化完全对得上，下篇展开聊。
