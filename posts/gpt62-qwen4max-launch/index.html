GPT-6.2 降价 20%，Qwen4-Max 单任务成本砍掉 58%：这周大模型比的其实不是谁最强

技术资讯 2026-11-21 约 12 分钟读完 · 阅读 - 次

这两天的两场发布，其实是同一件事的两面。

一边是 OpenAI，11 月 18 日正式放出 GPT-6.2 Astra 和 GPT-6.2 Sol；另一边是阿里，11 月 16 日发布 2.4 万亿参数的 Qwen4-Max。把发布会上的表格拉平来看会发现一件事——现在的竞争，已经不在「谁更聪明」这一栏了，而在「一个真实任务跑完要花多少钱」。

GPT-6.2：旗舰降价，日常款不动

先说 OpenAI。Astra 定位是复杂专业项目，每百万 token 输入 8 美元、缓存输入 0.4 美元、输出 40 美元，相比上一代 GPT-6 Astra，输入输出都降 20%，缓存输入直接砍掉 60%。Sol 走日常路线，2 美元 / 0.1 美元 / 10 美元，沿用 GPT-6.1 Sol 的价格没动。

缓存降 60% 这件事，体感上比降价 20% 更狠。长任务里系统提示、工具定义、多轮上下文都要反复读，这些 token 几乎全走缓存命中。

图源：机器之心《刚刚，OpenAI发布GPT-6.2 Astra和Sol》推文截图

首发入口集中在 ChatGPT Work、Codex 和 API，模型名就是 gpt-6.2-astra 和 gpt-6.2-sol，发布之初就带 Ultrafast 模式。Pro 500 用户两款都能用 Ultrafast，Pro 200 这次第一次拿到 Sol 的 Ultrafast 权限。普通 ChatGPT 聊天模式暂时没同步，得走 Work 或 Codex。

成绩单值得抄一下：衡量多步骤专业工作能力的 Agents’ Last Exam v1.1 里，Astra 比 GPT-6 Astra 高 5.2 分，单任务成本不到上代三分之一；对比 Claude Fable 5.2，高 5.5 分，成本只有对方的 5%。Terminal-Bench-Science 0.1 高出 9 个百分点，GDPval v2 高 6.2 分同时输出 token 少 22%。Artificial Analysis 的 AA-3D 上拿到 1318 Elo 排第一。

图源：机器之心《刚刚，OpenAI发布GPT-6.2 Astra和Sol》官方评测图

Sol 是另一套打法：Cognition 的 FrontierCode 2.0 上跟 Astra 差不到 0.5 分，成本约为五分之一；LifeVal 日常任务评测里得分反超 GPT-6 Astra，成本约为七分之一。写代码这种日常活儿，别默认开旗舰。

Tip

官方给的 Agents’ Last Exam 单任务成本参考：Astra 大约 3 美元，Claude Fable 5.2 大约 60 美元。同一张图里，Claude Fable 5.2 的成本标到 60 美元轴最右端，成绩和 GPT-6.2 Astra 挤在一起。这个成本/成绩比，比单纯的榜单排名更值得在选型时看。

抱怨也是真实的

发布会之后开发者圈的反响并不全是掌声。

开发者 Theo Browne 写了一篇《Why I hate GPT-6.2 Astra》，吐槽得很具体：他让 Astra 给《Outer Wilds》做一个新关卡，模型跑了两个小时，最后因为「r24 的 reviewer 该不该把片段写进 24_g521.mp4 还是 24_p11.mp4」这种内部命名细节停下来问他；拿自己的 Rust 编译器项目 ts-rust 做测试，Astra 连跑七天没带来任何性能提升，编译器速度反而慢了 56%，改口让它优化性能后再跑四天，依然没有有效改动。

图源：机器之心《刚刚，OpenAI发布GPT-6.2 Astra和Sol》推文截图

Every 创始人 Dan Shipper 说得更直接：团队提前测了几周，Astra 的写作表现甚至不如上一代，太追求简洁和可执行性，反而让人看不懂它做了什么；真实开发任务里它经常过早停止。沃顿商学院的 Ethan Mollick 认为 Astra 表现不均衡，比别的模型更难引导。

OpenAI 自己也承认了一个问题：在两项对齐测试中，两款模型更容易省略那些阻碍任务完成的问题，比如缺少文件、搜索工具不可用这种「本该先问一句」的场景。

我觉得这才是这轮发布里最值得开发者记住的部分：官方给的分数是横截面，开发者骂的是纵截面——模型在长任务里什么时候该自己拿主意、什么时候该停下来问人，这个边界远没有解决。

Qwen4-Max：把成本曲线压得更狠

阿里的动作更「工程」，也更适合中国开发者看。

Qwen4-Max 总参数 2.4 万亿，每 token 只激活 710 亿，比同规模的 Qwen3.8-Max 少了 25%，另配 3280 亿 N-gram Embedding 参数。上下文 100 万 token，原生视觉输入。

架构上换成新的 Qwen4 稀疏 MoE：每四层里三层用 Gated DeltaNet 把历史压成固定状态（KV 缓存不随上下文增长），一层用 Qwen Sparse Attention 按 block 粒度选关键上下文，官方说百万 token 读取速度提升 7 倍以上；残差流扩成 4 条并行分支并配动态读写门控，训练全程没出现 Loss Spike。

图源：阿里云官方《Alibaba Unveils Qwen4-Max》发布素材

效果上，Work360 这个覆盖 721 个细分领域的行业评测里得分 52.69，上一代 47.74，CodeArena 前端编程盲测全球第六。

真正的杀手锏是成本：Work360 上单任务平均费用从 26.58 元降到 11.16 元，降幅 58%；Token 消耗减少 24%-35%。百炼平台上的 API 定价是输入 10 元/百万、输出 30 元/百万、缓存命中 0.5 元/百万，缓存价格较上代降了约 70%。

它还做了个叫 Live Delivery 的机制，长任务不让你干等——先交一版能用的，你审阅校准方向，它接着迭代。演示案例包括：汽车零部件的 CAM 编程人工时间从约 475 分钟压到 24 分钟；48 小时自主跑完 270 万分子的候选空间并在实验室合成验证了一个数据中心冷却液分子；IPO 尽调场景把 198 份杂乱文件归成 14 个目录，交叉核对公开信息后交出 86 页带引用的报告；金融场景调用 90 个 MCP 工具，产出可编辑的 Excel 底稿和 PPT，每个数字都能溯源。

腾讯那边也没闲着，混元 Hy4 flash 的 API 价格压到每百万 token 输入 0.5 元、输出 2 元，单任务成本只有 Hy4 标准版的二十分之一，明确主打文档处理、PPT 生成、深度搜索和日常办公。

那我该怎么选

我现在的做法是按任务分层路由，而不是按「谁最强」选一个模型吃到底：

两条经验值：一，缓存命中率决定你的实际账单，长系统提示、工具定义多的 Agent 场景优先选缓存价低的模型；二，先用便宜档跑通再升级，别一上来就旗舰，OpenAI 自己的数据也支持这个顺序——Sol 的编程成绩只比 Astra 低 0.5 分。

还有一个变化值得留意：大模型商业化正在从「按 Token 付费」走向「按任务价值付费」。据经济参考报的梳理，厂商的计费已经分成 Token 后付费、订阅制、平台+模型双层计费、多模态单独计费和企业私有化部署几层，计费单位正从「调用量」细化到「任务价值、场景深度和服务等级」。

对开发者的实际含义是：以后谈采购，谈的可能不再是「每百万 token 多少钱」，而是「这个任务多少钱交付」。
