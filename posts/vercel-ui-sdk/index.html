Vercel 把界面拆成「行为」：UI SDK beta 让 Agent 不只会造 UI，还能反过来操作 UI

技术资讯 2026-11-22 约 13 分钟读完 · 阅读 - 次

今天前端圈最值得聊的一条，不是某个模型又涨了多少分，而是 Vercel Labs 把界面拆开了。

11 月 12 日，Vercel Labs 开源了 UI SDK，仓库在 vercel-labs/ui，许可证 Apache-2.0，发布当天就是 0.1.0-beta.1，第二天 core 加五个框架适配器一起升到 0.1.0-beta.2（DEV 社区报道）。shadcn 也参与了这件事，他在 X 上的说法很直接：“Agents are becoming both the builders and the users of interfaces.”（智能体既是界面的建造者，也是界面的使用者。）

图源：Vercel UI SDK 官网 ui-sdk.dev

它不是组件库，是行为层

大多数 UI 库给你的是组件：给你一个 <Select>、一个 <Combobox>、一个 <Dialog>，你往里塞 props。UI SDK 给的是另一层东西——行为。

核心包 @ui-sdk/core 里塞了 50 多个无头行为，包括 createPopup、createSelection、createTypeahead、createRovingFocus、createReorder、createResize、createViewport、createListbox、createChange、createFocusRecovery、createVirtualizer（InfoQ 报道）。焦点管理、键盘导航、选中、弹层、拖拽、虚拟列表这些平时每个项目都要重写一遍、每次重写都漏掉几个无障碍细节的逻辑，现在被抽成了可复用的原语。

组合方式是三步：

definePrimitive 声明一个组件的状态、对外 API 和插槽，createParts 把它渲染到不同框架。渲染出来的 parts 不带样式，只暴露属性和 CSS 变量，视觉完全交给项目自己。同一套行为还撑起了 50 多个无样式组件，Color Picker、Token Input、Command、Calendar、Tree、OTP Input 都在里面，五个适配器里 part 名字保持一致。

这里跟 Radix UI、Base UI、React Aria、Ark UI（它那套 Zag.js 状态机）、Headless UI 的差别很清楚：那些库也做无头，但基本都是 React 优先，各写各的。UI SDK 想做的是行为定义一次、五个框架渲染同一份逻辑。shadcn/ui 则站在更上面一层，是拷进你自己仓库的组件包。

Note

迁移成本其实不高。UI SDK 的更新日志直接给 Radix、Base UI、React Aria、shadcn/ui、Nuxt UI、Geist 致谢，用的是同一套「行为 + parts」的心智模型，你现在会写 Radix，概念上是通的。

更狠的是 Agent 那半边

真正让我觉得有意思的不是 50 个行为，而是 createAgent。

从 @ui-sdk/react/agent 导入它，页面上所有 UI SDK 组件就被挂上了一层桥。Agent 拿到三个原语：

  • snapshot()：读出页面上所有组件的当前状态
  • act()：直接调用组件 API，比如按 label 给某个输入框写值
  • query()：查询

也就是说，Agent 不需要截图、不需要扒 DOM，也不需要靠坐标点击。它和界面之间有了一份语义契约。

更狠的是控制权设计。应用可以通过 allow 决定放不放行 Agent 的动作；变更回调里 source 会标出是 "agent" 还是 "user"，应用可以直接 cancel 掉一次 Agent 造成的修改。registerTools 还能把同样的方法通过 WebMCP 暴露给浏览器内置的 Agent（前提是浏览器提供 document.modelContext）。

那组数据，我买一半

Vercel 自己跑了一个对比：同样一个设置页任务，浏览器工具方式需要 16 次工具调用、读取 3.98 万字符、耗时 41 秒；走 UI SDK 桥只要 5 次调用、6.8 千字符、16 秒。换算下来工具调用少了 69%、耗时快了 61%，单任务成本从 0.073 美元降到 0.032 美元（byteiota 的拆解）。

这个方向我认。截图看界面，2400 到 3000 个 token 一张；扒原始 DOM，五万个 token 起步；Agent 每多看一次页面，钱就多烧一截。而 UI SDK 把「读界面」变成了「读状态」，这是量级上的差别，不是优化。

Warning

这是一个任务、三次运行的自我报告，浏览器那侧用的还是另一套组件库，Vercel 也没公布用的哪个模型版本。这种 benchmark 顶多算 demo，不算结论。真要用在自己的项目里，得拿自己的界面自己测一遍。

我更在意的那个风险

README 里有一句话，冷得让我停下来：

“Don’t worry, you don’t need to learn how to write this. Your agents will.”

（别担心，你不需要学怎么写，你的 Agent 会。）

这句话既是它最大的机会，也是最大的坑。

机会在于，它把「交互质量」这件事的门槛从「人」转移到了「Agent」。做团队组件库、维护无障碍规范、给新人做 Code Review——这些活儿以前是人的负担，现在可以交给一个装了 ui-sdk 技能的 Agent 去执行。

坑在于，行为是可组合的，也就是可省略的。有开发者试过让 Agent 做一个团队成员选择器：Agent 拿到 createPopup 和 createSelection，跳过了 createListbox，自己手搓了方向键逻辑。看起来没问题，Tab 进去之后焦点直接消失在弹层里，出不来。同一个模型、同一个包，换一种问法（「用 createListbox 处理方向键」）结果就干净了。

也就是说，UI SDK 的 skill 不是编译器，它更像一个提醒。行为给你了，用不用、会不会用，取决于描述交互的方式有多清楚。这跟 shadcn 那套「复制粘贴式」的组件库体验是反的——组件库是给你现成的答案，行为层是给你一套材料，成品质量看谁在搭。

谁该现在上

我的判断分三档：

  • 正在给 Agent 做前端工具链的团队，值得立刻试。这是目前第一个把「Agent 操作界面」做成一等公民、而不是靠截图 + 坐标糊出来的方案。哪怕只先用 createAgent 那半边，拿它做已有界面的自动化测试，价值就已经出来了。
  • 想统一 React / Vue / Svelte 多端交互一致性的团队，definePrimitive + createParts 的思路值得试，尤其是要维护设计系统的团队。
  • 只是想找个稳定的无头库做业务组件的，我建议先观望。Base UI 还在 React-only 但维护团队是全职的，类型干净，Radix 那边因为并购后动作偏慢；UI SDK 现在是 beta，官方明说 API、文档和行为都可能在 GA 前变。它唯一的护城河是那座 Agent 桥，如果你的项目里没有 Agent 场景，Base UI 更保守、更省心。

还有一个事实要摆在桌面上：仓库从零到四千多 star 只用了十九天，热度不假，但热度不等于稳定。反过来看，这个领域的迭代节奏只会更快——Storybook 11 beta 也在同期塞进了官方 skills 和 headless CLI，方向是一回事：把「给 Agent 喂上下文」做成基础设施，而不是每个团队自己造轮子。

几条同向的消息

  • Storybook 11 beta 带来官方 skills 与 headless CLI，宣称上下文交付比 v10 快最多 10 倍，包体积还小了 25%（Storybook 博客）
  • Next.js 把 AI 漏洞发现做进了日常流程，今年已经产出 51 个安全公告，每个 PR 都会过一遍对抗式安全 Agent（This Week In React #306）
